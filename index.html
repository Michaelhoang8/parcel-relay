What this demonstrates

The sender commits a shipment and its outbox event together. The receiver commits its inbox receipt and inventory changes together. Those are separate transactions: there is no distributed transaction between them.

Delivery is a local call with explicit fault injection, not a live message broker. Delivery attempts are manual. The inbox retains event IDs; this gives one inventory effect per retained ID, not exactly-once transport. Additive inventory updates tolerate reordering. Each database is read separately, so refresh during concurrent writes may briefly show different moments.

Checksums detect accidental changes; they are not authentication. This local teaching app has no accounts or remote deployment configuration.
